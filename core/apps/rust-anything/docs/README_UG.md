**پۈتۈن ئەپىڭىزنى Rust دا پارچىمۇپارچە قايتا يېزىڭ.** rust-anything سىزنىڭ Node.js (TypeScript/JavaScript)،
Python، C، Go، Ruby ياكى Java ئەپىڭىزنىڭ بۈگۈن نېمە قىلىدىغانلىقىنى خاتىرىلەيدۇ، ئاندىن ئالدىغا ئىلگىرىلەشتىن بۇرۇن
Rust دا قايتا يېزىلغان ھەر بىر پارچىنى شۇ خاتىرە بىلەن سېلىشتۇرۇپ تەكشۈرىدۇ، ئەپ ساپ Rust بولغۇچە. CLI، HTTP
مۇلازىمېتىرلىرى ۋە كۇتۇپخانىلار؛ Rust كودىنى سىزنىڭ پروگرامما ئاگېنتىڭىز (ياكى سىز ئۆزىڭىز) يازىدۇ. ئۇ پەقەت
خاتىرە قاپلىغان نەرسىلەرنىلا تۇتالايدۇ: [ئۇ نېمىلەرنى تۇتالمايدۇ](#ئۇ-نېمىلەرنى-تۇتالمايدۇ) غا قاراڭ. پەقەت ئاستا قىسمىنىلا تېزلەتمەكچىمۇ؟
شۇنىلا كۆچۈرۈڭ، ھەر قېتىمدا بىر ئىسسىق يول (hot path):

| ھەقىقىي يۈك، نەتىجىسى ئەسلى نۇسخا بىلەن ئوخشاش | ئەسلى نۇسخا | rust-anything بىلەن |
| --- | ---: | ---: |
| x18n نىڭ يان تاختا ئىزدىشى، 50,000 ئاچقۇچ (TypeScript، Node) | ھەر سوئالغا 10 ms | **0.5 ms: 20x تېز** |
| ئوخشاش ئىزدەش توركۆرگۈدە (wasm، بىر ئېقىم) | 10 ms | **0.95 ms: 11.5x** |
| 20,000 قۇرغا `slugify` (Python) | 98 ms | **17x تېز** |
| Ruby نىڭ ئۆلچەملىك كۇتۇپخانىسىدىكى `Shellwords.shellescape`، 50,000 قىممەت | 88 ms | **11.8x تېز** |
| 50,000 قۇرغا `Slugify` (Go) | 49 ms | **4x تېز** |
| 50,000 قۇرغا `slugify` (Java) | 43 ms | **3x تېز** |

4 يادرودا ئۆلچەندى؛ ھەر بىر سانىنىڭ [`demo/`](../demo) ئىچىدە benchmark ى بار، ئۇ ئالدى بىلەن
نەتىجىلەرنىڭ ئوخشاشلىقىنى تەكشۈرىدۇ. ھەر بىر كىچىك فۇنكسىيە ئۈچۈن Rust نى ئايرىم چاقىرىش ئادەتتە JIT تىن *ئاستا*؛
rust-anything كۆچۈرۈشكە ئەرزىيدىغان ئايلانمىنى تاپىدۇ ۋە ئۇنى كۆچۈرىدۇ.

> rust-anything مۇستەقىل تۈر، ئۇ Rust Project ياكى Rust Foundation بىلەن مۇناسىۋەتلىك ئەمەس ۋە ئۇلار تەرىپىدىن تەستىقلانمىغان.
> "Rust" بولسا Rust Foundation نىڭ سودا ماركىسى.

## تېز باشلاش

بۇنى Claude Code، Codex، Cursor ياكى Gemini CLI غا چاپلاڭ، ئاگېنتىڭىز ئۇنى ئورناتسۇن:

</div>

```text
rust-anything نى ئورنات: `cargo install rust-anything` نى ئىجرا قىل، ئاندىن `rust-anything setup` نى.
سېنى قاچان قايتا قوزغىتىشىم كېرەكلىكىنى ماڭا ئېيت.
```

<div dir="rtl">

ياكى ئۆزىڭىز:

</div>

```sh
cargo install rust-anything   # crates.io دىن
rust-anything setup           # ئۇنى Claude Code، Codex، Cursor ۋە Gemini CLI دا تىزىملايدۇ
```

<div dir="rtl">

تېخى Rust toolchain يوقمۇ؟ macOS، Linux ۋە Windows ئۈچۈن تەييار ئىككىلىك ھۆججەتلەر ھەر بىر
[GitHub release](https://github.com/erkamyaman/rust-anything/releases) غا قوشۇپ قويۇلغان، JavaScript
تۈرلىرى ئۈچۈن `npm install -g rust-anything` ئوخشاش ئىككىلىك ھۆججەتنى ئورنىتىدۇ.

Claude Code دا ئۇنى قىستۇرما (plugin) سۈپىتىدىمۇ ئورناتقىلى بولىدۇ (MCP مۇلازىمېتىرى ۋە skill؛ يۇقىرىدىكى CLI
`PATH` ىڭىزدا بولۇشى كېرەك):

</div>

```text
/plugin install rust-anything --marketplace erkamyaman/rust-anything
```

<div dir="rtl">

`setup` تاپقان ھەر بىر ئاگېنتقا MCP مۇلازىمېتىرىنى قوشىدۇ ۋە workflow skill نى ئاگېنت skill لارنى ئوقۇيدىغان
ئورۇنغا ئورنىتىدۇ. ئۇ باشقا تەڭشەكلىرىڭىزنى ساقلايدۇ، قايتا ئىجرا قىلىش بىخەتەر، `--remove` بولسا ئۇنى ئەمەلدىن قالدۇرىدۇ.
ئاندىن ئاگېنتىڭىزدىن سوراڭ، مەسىلەن:

- *"بۇ CLI نى rust-anything ئارقىلىق باشتىن ئاخىرىغىچە Rust دا قايتا يېزىپ، ئۇنىڭ ئوخشاش ئىشلەيدىغانلىقىنى ئىسپاتلا."*
- *"بۇ ئىزدەش ئاستىدەك تۇرىدۇ. ئۇنى rust-anything بىلەن profile قىلىپ، ئىسسىق ئايلانمىنى Rust قا يۆتكە."*
- *"rust-anything بىلەن `src/parser/` نى Rust قا كۆچۈرۈشنى پىلانلا؛ بىرىنچى بىرلىكنى كۆچۈرۈپ ئىسپاتلا."*
- *"`rust/text-rs` دىكى Rust كۆچۈرمىسىنى ئەسلى نۇسخا بىلەن benchmark دا سېلىشتۇرۇپ، ئېلان قىلىشقا بولامدۇ ئېيت."*

### ماس كېلىدىغان ئاگېنتلار

| ئاگېنت | `rust-anything setup` نېمە قوشىدۇ |
| --- | --- |
| Claude Code | `~/.claude.json` دا MCP مۇلازىمېتىرى، `~/.claude/skills/` دا skill |
| Codex | `~/.codex/config.toml` دا MCP مۇلازىمېتىرى، `~/.codex/skills/` دا skill |
| Cursor | `~/.cursor/mcp.json` دا MCP مۇلازىمېتىرى |
| Gemini CLI | `~/.gemini/settings.json` دا MCP مۇلازىمېتىرى |
| باشقا ھەر قانداق MCP خېرىدارى | `rust-anything mcp` نى stdio مۇلازىمېتىرى سۈپىتىدە قولدا قوشۇڭ ([ئورنىتىش](#ئورنىتىش) قا قاراڭ) |

مەۋجۇت ھۆججەتنى ئۆزگەرتىشتىن بۇرۇن، `setup` ئۇنىڭ يېنىغا بىر نۇسخىسىنى ساقلايدۇ (`<file>.rust-anything.bak`).

ياكى قەدەملەرنى ئۆزىڭىز ئىجرا قىلىڭ:

<p align="center">
  <img src="assets/terminal.gif" alt="rust-anything profile ئايلانما ئىچىدىكى fuzzyScore نى تاپىدۇ، bridge --batch Rust crate نى ھاسىل قىلىدۇ، gate خاتىرىلەنگەن 2000/2000 ئەھۋال بىلەن ئۆتىدۇ، benchmark بولسا TS تىن 20.7x تېز ئىكەنلىكىنى كۆرسىتىدۇ." width="820">
</p>

</div>

```sh
rust-anything profile . -- node bench.mjs              # نېمە ئىسسىق، ئۇنى كىم چاقىرىدۇ
rust-anything bridge . src/fuzzy.ts --batch fuzzyScore:text
# src/port.rs نى يېزىڭ (ياكى ئاگېنتىڭىزغا يازدۇرۇڭ)، ئاندىن:
rust-anything record rust/fuzzy-rs && rust-anything build rust/fuzzy-rs
rust-anything diff rust/fuzzy-rs                       # خاتىرىلەنگەن ھەر بىر ئەھۋال ماس كېلىشى كېرەك
rust-anything bench rust/fuzzy-rs                      # تېزمۇ؟ ھۆكۈم ئېيتىدۇ
rust-anything gate rust/fuzzy-rs                       # بۇ ئۆتسە، ئىش تامام
```

<div dir="rtl">

rust-anything كودنى تەرجىمە قىلمايدۇ: Rust كودىنى سىزنىڭ پروگرامما ئاگېنتىڭىز (Claude Code، Codex، Cursor، ...) ياكى
سىز ئۆزىڭىز يازىسىز. rust-anything ئاگېنت ئىشەنچلىك پەرەز قىلالمايدىغان نەرسىلەرنى تەمىنلەيدۇ: ۋاقىت قەيەرگە كېتىدۇ، نېمىنى
ئالدى بىلەن ۋە قايسى تەرتىپتە كۆچۈرۈش، قالغان كود Rust نى API ئۆزگەرمىگەن ھالدا چاقىرالىشى ئۈچۈن bridge،
كۆچۈرمە ماس كېلىشى كېرەك بولغان ئېنىق ھەرىكەت، ئۇنى ئېلان قىلىشنىڭ بىخەتەر ئۇسۇلى ۋە كۆچۈرمىنىڭ قاچان
تامام بولغانلىقىنى ئېيتىدىغان gate.

## تىللار

| تىل | بىرلىك | Bridge | خاتىرىلىگۈچى ۋە قايتا قويغۇچى |
| --- | --- | --- | --- |
| TypeScript/JavaScript | قىسقۇچ ياكى ھۆججەت | ھاسىل قىلىنغان ئىككىلىك wire فورماتلىق napi-rs ياكى wasm-bindgen؛ كلاس ۋە async مۇ بار | Node، `.ts` مەنبە ھۆججەتلىرىنى ئىجرا قىلىپ |
| Python | بوغچا ياكى مودۇل | PyO3 (abi3)، بىۋاسىتە ئايلاندۇرۇش، تىپلىق مۇستەسنالار | Python، ئەسلى نۇسخىنى import قىلىپ |
| C | `.c` ھۆججىتى | ئەسلى ناملىق `extern "C"` فۇنكسىيەلىرى ۋە header | ئورتاق كۇتۇپخانىغا تەرجىمە قىلىنغان ئەسلى نۇسخا، ctypes ئارقىلىق چاقىرىلىدۇ، ھەر ئەھۋالغا بىر fork |
| Go | بوغچا | تىپلىق cgo چاقىرىقلىرى ۋە ھاسىل قىلىنغان ئىككىلىك wire فورماتى، ئەسلى API لىق بوغچىدا | ھاسىل قىلىنغان Go قوزغاتقۇچىسى، ئايرىم مودۇل سۈپىتىدە قۇرۇلىدۇ |
| Ruby | مودۇل فۇنكسىيەلىرى بار ھۆججەت ياكى قىسقۇچ | ئەسلى مودۇللار ئاستىدىكى magnus كېڭەيتمىسى | ھاسىل قىلىنغان Ruby قوزغاتقۇچىسى |
| Java | `public static` مېتودلىرى بوغچىسى | تىپلىق JNI ۋە ھاسىل قىلىنغان ئىككىلىك wire فورماتى، ئەسلى مېتودلىق wrapper كلاسلىرىدا | ھاسىل قىلىنغان reflection قوزغاتقۇچىسى |
| PHP (preview) | فۇنكسىيەلەر ۋە `public static` مېتودلىرى قىسقۇچى | كېيىنكى قەدەم: C ABI ئۈستىدە PHP FFI | بۈگۈندىلا پۈتۈن ئەپلەر: `app record`، `app replay` ۋە front door، CLI ۋە مۇلازىمېتىرلار ئۈچۈن (`php -S`) |
| C# (preview) | `public static` مېتودلىرى قىسقۇچى | كېيىنكى قەدەم: C ABI ئۈستىدە P/Invoke | بۈگۈندىلا پۈتۈن ئەپلەر: `app record`، `app replay` ۋە front door، CLI ۋە ASP.NET مۇلازىمېتىرلىرى ئۈچۈن (`dotnet <app>.dll`) |

C دىن باشقا ھەر بىر تىل batch كلاسلىرىغىمۇ (`--batch`) ئېرىشىدۇ: ئېلېمېنتلار بىر قېتىم ئۆتۈپ
Rust تا قالىدۇ، ھەر بىر چاقىرىق ئۇلارنىڭ ھەممىسىنى بارلىق يادرولاردا بىر تەرەپ قىلىدۇ.

تىل ئامباردىن (repository) بايقىلىدۇ (`go.mod`، `pom.xml`، `.csproj` ياكى `.sln`،
`pyproject.toml`، `Gemfile`، `composer.json`، `package.json`، بولمىسا ئەڭ كۆپ ئۇچرايدىغان مەنبە ھۆججەتلەر)؛
`--lang` ئۇنى قاپلايدۇ. تىپلار مەنبە كودتىن ئېلىنىدۇ: TS تىپلىرى، Python type hints، C، Go، Java ۋە C#
ئىمزالىرى، Ruby YARD بەلگىلىرى، PHP تىپلىرى ۋە phpdoc؛ سان سۈپىتىدە ئىشلىتىلگەن تىپسىز پارامېتىرلار
سان دەپ پەرەز قىلىنىدۇ.

PHP سىناق نۇسخىسىدا: `analyze` PHP ئەپىنى پىلانلايدۇ (Composer بوغچىلىرى ۋە PSR-4 autoloading، بوش
سېلىشتۇرۇش ۋە پۈتۈن سانلارنىڭ float قا تېشىپ كېتىشىگە ئوخشاش خەتەرلەر، Composer بوغچىلىرىغا ماس crate لار)،
PHP CLI ياكى مۇلازىمېتىرىنى خاتىرىلەپ، قايتا قويۇپ، Rust front door نىڭ ئارقىسىغا قويغىلى بولىدۇ. ئۇنىڭ
بىرلىكلىرىنى PHP FFI ئارقىلىق Rust قا كۆچۈرۈش كېيىنكى قەدەم ([issue #2](https://github.com/erkamyaman/rust-anything/issues/2)).

C# مۇ ئوخشاشلا سىناق نۇسخىسىدا: `analyze` `.csproj` تۈرلىرى ۋە ئۇلارنىڭ NuGet بوغچىلىرىنى ئوقۇيدۇ
(crate لارغا ماسلاشتۇرۇپ)، `using` كۆرسەتمىلىرىنى قىسقۇچلارغا باغلايدۇ ۋە C# نىڭ ئوخشىمايدىغان جايلىرىنى بەلگىلەيدۇ
(`decimal`، `dynamic`، LINQ نىڭ كېچىكتۈرۈلگەن سوئاللىرى، `Task`، `lock`، reflection). C# CLI ياكى ASP.NET
مۇلازىمېتىرىنى خاتىرىلەپ، قايتا قويۇپ، Rust front door نىڭ ئارقىسىغا قويغىلى بولىدۇ؛ بىرلىكلەرنى P/Invoke ئارقىلىق كۆچۈرۈش
كېيىن كېلىدۇ.

## قانداق ئىشلەيدۇ

</div>

```

 where the    what to     the Rust   what the    you or      every     faster?    both side   done means
 time goes    port first  crate and  original    your agent  recorded  the        by side in  this passes
                          wrapper    does        write it    case      verdict    production
```

<div dir="rtl">

ئەسلى نۇسخا ھەقىقەت مەنبەسى بولۇپ قالىدۇ: `record` ئۇنى چېگرا ئەھۋاللاردا (ۋە سىزنىڭ ئۆز كىرگۈزۈشلىرىڭىزدە) ئىجرا قىلىپ،
ئۇنىڭ نېمە قايتۇرغانلىقى ياكى نېمە تاشلىغانلىقىنى ساقلايدۇ؛ `diff` ھەر بىر ئەھۋالنى Rust قا قارىتا قايتا قويىدۇ؛ ھەممىسى
ماس كەلمىگۈچە ۋە `gate` ئۆتمىگۈچە ھېچنېمە ئېلان قىلىنمايدۇ. چاقىرغۇچىلار پۈتۈن جەرياندا ئەسلى API نى ساقلايدۇ.

پۈتۈن ئەپمۇ ئوخشاش ئايلانمىدىن بىرلىكمۇبىرلىك ئۆتىدۇ، پۈتۈن پروگراممىنى ئىسپاتلايدىغان رامكا ئىچىدە
([پۈتۈن ئەپنى كۆچۈرۈش](#پۈتۈن-ئەپنى-كۆچۈرۈش)):

| قەدەم | بۇيرۇق | نېمە قىلىدۇ |
| --- | --- | --- |
| 0. Profile | `rust-anything profile <repo> -- node bench.mjs` | ھەقىقىي يۈكنى تىلنىڭ profiler ى ئاستىدا ئىجرا قىلىدۇ (node، cProfile، `go test` pprof، JFR، Ruby ئىز قوغلىغۇچىسى): ئومۇمىي ۋاقىت بويىچە ئىسسىق فۇنكسىيەلەر، ئۇلارنى چاقىرغۇچىلار ۋە قايسى ئايلانمىلارنى batch قىلىش؛ ئاللىقاچان تەرجىمە قىلىنغان كودنى (numba، Cython، JAX) بەلگىلەيدۇ، ئۇ يەردە Rust ئاز پايدا بېرىدۇ |
| 1. پىلان | `rust-anything analyze <repo>` | بىرلىكلەر، كۆچۈرۈش تەرتىپى، `file:line` بىلەن خەتەرلەر، ھەر بىرلىككە bridge، تايىنىشلارنىڭ crate لارغا ماس كېلىشى، ئەڭ ياخشى دەسلەپكى كۆچۈرمىلەر؛ `--whole-app` كىرىش نۇقتىلىرى ۋە شەكلىنى، ھەر بىر تايىنىشنى (import قىلىنغان ياكى ئېلان قىلىنغان) crate ى بىلەن، پارچىلارنى (بىر-بىرىنى import قىلىدىغان بىرلىكلەر بىللە كۆچىدۇ) ۋە تەۋسىيە جاۋابلىق نومۇرلانغان قارارلارنى قوشىدۇ |
| 2. Bridge | `rust-anything bridge <repo> <unit>` | Bindings بار crate (`lib.rs`، يەنە مەنبە تىل يۈكلەيدىغان wrapper) ۋە كۆچۈرۈش ئۈچۈن stub لار (`port.rs`)؛ `--batch fn:param` نۇرغۇن `param` قىممىتىنى Rust تا ساقلايدىغان كلاس قوشىدۇ |
| 3. خاتىرىلەش | `rust-anything record <crate>` | ئەسلى نۇسخىنى ھاسىل قىلىنغان چېگرا ئەھۋاللاردا (ASCII ئەمەس، emoji، `-0`، `NaN`، float كۈتۈلگەن يەردە پۈتۈن سان، ...) ۋە ھەر بىر پارامېتىردىكى ھەر بىر مەنىۋى تۇزاقتا (قۇر ئۇزۇنلۇقى ۋە چوڭ-كىچىك ھەرپ، بەلگىلىك بۆلۈش، تېشىش چېگرىلىرى، float بېسىش، map ۋە تەرتىپلەش تەرتىپى) ئىجرا قىلىپ `cases.jsonl` نى ساقلايدۇ؛ `--float-tolerance 1e-9` سانلىق كود ئۈچۈن float لارنىڭ شۇ ئۈلۈش ئىچىدە ماس كېلىشىگە يول قويىدۇ |
| 3. قۇرۇش | `rust-anything build <crate>` | Rust تەرىپىنى قۇرىدۇ: `.node`، wasm بوغچىسى، Python كېڭەيتمىسى ياكى ئورتاق كۇتۇپخانا |
| 3. Diff | `rust-anything diff <crate>` | خاتىرىلەنگەن ئەھۋاللارنى Rust قا قارىتا قايتا قويىدۇ، ئەسلى نۇسخىنى چاقىرغۇچىلار قانداق چاقىرسا شۇنداق چاقىرىپ؛ ماس كەلمەسلىكلەرنى تىزىدۇ |
| 3. Bench | `rust-anything bench <crate>` | خاتىرىلەنگەن ئەھۋاللارنىڭ ۋاقتىنى ئەسلى نۇسخىدا ۋە Rust تا ئۆلچەيدۇ، bridge مۇ ئىچىدە |
| 4. Shadow | `rust-anything shadow <crate>` | ئىككىلىسىنى ئىجرا قىلىدىغان، ئەسلى نۇسخىنىڭ نەتىجىسىنى قايتۇرىدىغان، ماس كەلمەسلىكلەرنى دوكلات قىلىدىغان drop-in ئالماشتۇرغۇچ؛ `RUST_ANYTHING_MODE=old\|shadow\|new` |
| 5. Gate | `rust-anything gate <crate>` | fmt، clippy `-D warnings`، سىناقلار، `unsafe` تەكشۈرۈش، كۆچۈرۈلمىگەن ھېچنېمە يوق، ئەسلى نۇسخىنىڭ ھەر بىر خاتالىق يولى ئۈچۈن خاتىرىلەنگەن مەغلۇب ئەھۋال، ئەسلى نۇسخا خاتالىق قايتۇرىدىغان يەردە `unwrap`/`expect`/`panic!` يوق (`// INFALLIBLE: <why>` دەپ بەلگىلەنمىگەن بولسا)، قۇرۇش، API، ھەرىكەت |
| ئاگېنتلار | `rust-anything setup` | MCP مۇلازىمېتىرى (`rust-anything mcp`، ھەر بىر قەدەم قورال سۈپىتىدە) ۋە workflow skill نى ([`skills/rust-anything/SKILL.md`](../skills/rust-anything/SKILL.md)) پروگرامما ئاگېنتلىرىڭىزدا تىزىملايدۇ |

## پۈتۈن ئەپنى كۆچۈرۈش

نىشان: ئەسلى نۇسخىدەك ئىشلەيدىغان ساپ Rust ئەپى، ئەسلى نۇسخا بولسا پايدىلىنىش سۈپىتىدە ساقلىنىدۇ.
Rust كودىنى ئاگېنتىڭىز يازىدۇ؛ rust-anything ئىشنى تەرتىپكە سالىدۇ، ئاساسىي قۇرۇلمىسىنى ياسايدۇ ۋە ھەر بىر قەدەمنى ئىسپاتلايدۇ.
[Whole-app skill](../skills/rust-anything/whole-app.md) ئاگېنتنى قەدەممۇقەدەم يېتەكلەيدۇ، پەقەت
سىزلا قىلالايدىغان قارارلاردىن باشلاپ:

- **Grilling**: ئاگېنت سوئاللارنى ئايلانما بويىچە سورايدۇ، ھەر بىرى تەۋسىيە جاۋابى بىلەن، كۆچۈرمە تايىنىدىغان ھەر بىر
  قارار بېكىتىلگۈچە، ۋە ھەر بىرىنى `rust/DECISIONS.md` غا ADR سۈپىتىدە يازىدۇ،
  `rust/GLOSSARY.md` بولسا ئەسلى نۇسخىنىڭ ئاتالغۇلىرىنى Rust ناملىرىغا ماسلاشتۇرىدۇ.
- **Research**: ئارقا سۇپا ئاگېنتلىرى ھەر بىر تايىنىشنىڭ ئەسلى مەنبەلىرىنى ئوقۇپ، تاپقان ھەر بىر مەنىۋى تۇزاق بىلەن
  `rust/research/<topic>.md` نى يازىدۇ.
- **سۆھبەتلەر ئارىسىدا**: `rust/MAP.md` ھەر بىر بىرلىكنى ھالىتى بىلەن تىزىدۇ؛ بىر سۆھبەت باشلاشتىن بۇرۇن
  بىر بىرلىكنى ئۆزىگە ئالىدۇ، ھەر بىر تەكشۈرۈش نۇقتىسى كېيىنكى سۆھبەت ئۈچۈن `rust/HANDOFF.md` قالدۇرىدۇ. بىر
  دولقۇندىكى بىرلىكلەرنى قوشۇمچە ئاگېنتلار (subagents) پاراللېل كۆچۈرەلەيدۇ.
- **Cutover**: ئاگېنت قولىدىن كېلىدىغاننى قىلىپ، `rust/cutover.sh` نى يازىدۇ، بۇ پەقەت سىزلا قىلالايدىغان
  قەدەملەر (deploy، DNS، مەخپىي ئۇچۇرلار) ئۈچۈن ئۆز-ئارا تەسىرلىك قوليازما بولۇپ، ھەر بىر قەدەمدە قايتىش يولى بار.

Grilling، research ۋە بۇ ئۇسۇللار
[Matt Pocock نىڭ skill لىرى](https://github.com/mattpocock/skills) دىن ماسلاشتۇرۇلغان.

ئالدى بىلەن پىلان: `rust-anything analyze . --whole-app` ئەپنىڭ شەكلىنى (CLI، مۇلازىمېتىر ياكى كۇتۇپخانا)
ۋە كىرىش نۇقتىلىرىنى، ھەر بىر سىرتقى تايىنىشنى (import قىلىنغان ياكى ئېلان قىلىنغان) Rust crate ى ۋە ماسلىقى بىلەن،
كۆچۈرۈش تەرتىپىنى پارچىلار سۈپىتىدە (بىر-بىرىنى import قىلىدىغان بىرلىكلەر بىللە كۆچىدۇ) ۋە تەۋسىيە جاۋابلىق
نومۇرلانغان قارارلارنى قوشىدۇ: ساقلىنىدىغان بىرلىكلەر، توسۇلۇپ قالغان بىرلىكلەر، crate ى يوق ياكى قىسمەن بار تايىنىشلار.

ئاندىن پۈتۈن پروگراممىنى سىرتتىن ئىسپاتلاڭ. `record` ۋە `diff` بىر بىرلىكنى ئىسپاتلايدۇ؛ `app record`
ۋە `app replay` ئەپنى ئىسپاتلايدۇ، ئالتە تىلنىڭ خالىغان بىرىدىكى CLI ۋە مۇلازىمېتىرلار ئۈچۈن (ئەپ
قارا ساندۇق):

</div>

```sh
rust-anything app record . -- python3 cli.py          # ئەسلى نۇسخىنى ئىجرا قىلىدىغان بۇيرۇق
rust-anything app replay .                            # ئەسلى نۇسخا 100% ئۆتۈشى كېرەك
rust-anything app replay . --build "target/release/mytool"
```

<div dir="rtl">

- `app record` ئەسلى نۇسخىنى ئەپنىڭ ئۆز ھۆججەتلەشتۈرۈلگەن مىساللىرىدا (ئۇنىڭ Markdown ۋە shell ھۆججەتلىرىدىكى
  `$ mytool ...` قۇرلىرى، ئۇلار تىلغا ئالغان ھۆججەتلەر بىلەن)، `--inputs` JSONL ھۆججىتىدە
  (`{"name", "args", "stdin", "env", "files"}`) ۋە شۇ ئەھۋاللاردىن چىقىرىلغان مەنىۋى تۇزاقلاردا
  (ASCII ئەمەس ۋە emoji قۇرلار، مەنپىي بۆلۈش ۋە قالدۇق، تېشىش، چوڭ ۋە ناھايىتى كىچىك float لار،
  map تەرتىپى، يوق ھۆججەتلەر) ئىجرا قىلىدۇ. ھەر بىر ئەھۋال ئىككى قېتىم ئىجرا قىلىنىدۇ؛ ئىككى ئىجرا ئارىسىدا پەرقلىق بولغىنى
  `[..]` wildcard قا ئايلىنىدۇ. `--normalize timestamps|uuids|key-order` ياكى `--normalize name=regex`
  ئەھۋاللار بىلەن بىللە ساقلىنىدىغان نورماللاشتۇرغۇچلارنى قوشىدۇ.
- ئەھۋاللار `rust/app-cases/` دىكى [trycmd](https://docs.rs/trycmd) ھۆججەتلىرى: `<case>.toml` (argv، env،
  چىقىش كودى)، `.stdin`، `.stdout`، `.stderr`، `.in/` (كىرىدىغان ھۆججەتلەر) ۋە `.out/` (يېزىلغان ھۆججەتلەر). ئۇلارنى
  قولدا ئوقۇپ تەھرىرلەڭ؛ كۆچۈرمىنىڭ ئىككىلىك ھۆججىتى بولغاندىن كېيىن، Rust سىنىقى ئۇلارنى `trycmd` بىلەن ئىجرا قىلالايدۇ.
- `app replay` ھەر قانداق قۇرۇلمىنى ئەھۋاللارغا قارىتا ئىجرا قىلىپ، `passed/total` نى بېسىپ چىقىرىدۇ،
  ھەر بىر مەغلۇب ئەھۋال ئۈچۈن diff بىلەن `rust/app-cases/replay-report.md` نى يازىدۇ ۋە ھەر قانداق ماس كەلمەسلىكتە
  نۆلدىن باشقا كود بىلەن چېكىنىدۇ. `RUST_ANYTHING_FALLBACK_LOG` كۆرسەتكەن ھۆججەتكە قوشۇپ يازىدىغان قۇرۇلما (ئەسلى نۇسخىغا
  ھەر بىر fallback ئۈچۈن بىر قۇر)، تۆۋەندىكى front door قىلغاندەك، fallback نىسبىتىنىمۇ دوكلاتتا ئالىدۇ.
- `app replay --case <name>` بىر ئەھۋالنى دوكلات بەرگەن نامى بويىچە قايتا ئىجرا قىلىدۇ: ھەممىنى قايتا ئىجرا قىلىشتىن بۇرۇن
  ماس كەلمەسلىكنى تۈزىتىش ئۈچۈن تېز ۋە قايتىلىنىدىغان ئايلانما.

ئاندىن كىرىش نۇقتىسىنى Rust قا يۆتكەپ، ئۇنىڭغا بۇيرۇقلارنى بىرلىكمۇبىرلىك تاپشۇرۇڭ:

</div>

```sh
rust-anything app front-door .                            # rust/app: ھەر بىر بۇيرۇق ئەسلى نۇسخىنى ئىجرا قىلىدۇ
rust-anything app wire . textkit --command upper          # textkit-rs gate تىن ئۆتكەندىن كېيىن
# rust/app/src/units/textkit.rs غا glue كودىنى يېزىڭ، ئاندىن:
rust-anything app wire . textkit                          # يەنە 100%، fallback نىسبىتى تۆۋەنرەك
```

<div dir="rtl">

- `app front-door` ئەپنىڭ نامىدىكى Rust ئىككىلىك ھۆججىتى بولغان `rust/app` نىڭ ئاساسىي قۇرۇلمىسىنى ياسايدۇ: خاتىرىلەنگەن
  ئەھۋاللاردىكى بۇيرۇق ۋە بەلگىلەر ئۈچۈن clap تەھلىلچىسى، بۇ يەردە ھەر بىر بۇيرۇق ئەسلى نۇسخىنى ئوخشاش
  argv، stdin ۋە مۇھىت بىلەن ئىجرا قىلىپ، ئۇنىڭ چىقىرىشى ۋە چىقىش كودىنى ئۆتكۈزىدۇ. ھەر بىر fallback
  سانىلىدۇ، شۇڭا يېڭى front door نى قايتا قويۇش 100% fallback بىلەن 100% ئۆتۈش بېرىدۇ (ئۇ بۇنى كۆرسىتىش ئۈچۈن قۇرۇپ
  قايتا قويىدۇ). ئۇ `rust/app` نى ھەرگىز قاپلىمايدۇ: شۇنىڭدىن كېيىن كود سىزنىڭ.
- `app wire <repo> <unit> --command <name>` بىرلىك crate ىدا `gate` نى ئىجرا قىلىدۇ (يېڭىلا ئۆتكەن بولسا `--skip-gate`)،
  ئۇنى `rust/app` قا كۇتۇپخانا سۈپىتىدە قوشىدۇ، سىز ياكى ئاگېنتىڭىز تولدۇرۇش ئۈچۈن `src/units/<unit>.rs` نى بىر قېتىم يازىدۇ
  (پارامېتىرلارنى تەھلىل قىلىش، `<crate>::port` نى چاقىرىش، ئەسلى نۇسخا بېسىپ چىقارغاننى بېسىپ چىقىرىش)،
  بۇيرۇقلارنى ئۇنىڭغا يۆنىلىشلەيدۇ، ئاندىن قۇرۇپ قايتا قويىدۇ. `RUST_ANYTHING_UNIT_<NAME>=original` ئۇلانغان
  بىرلىكنى lift قا قەدەر ئەسلى نۇسخىغا قايتۇرىدۇ.

ھېچقانداق بۇيرۇقنى ئاتىمايدىغان argv ئۈچۈن (پارامېتىرسىز، نامەلۇم بۇيرۇقلار، ئىشلىتىش خاتالىقلىرى) ئەپنىڭ ئۆز نامىنى
بۇيرۇق سۈپىتىدە ئۇلاڭ (`--command mytool`).

Replay 0 fallback نىسبىتى بىلەن ئۆتكەندە ۋە ھەر بىر بىرلىك gate تىن ئۆتكەندە، ئۇنى ساپ Rust ئەپىگە ئايلاندۇرۇڭ:

</div>

```sh
rust-anything app lift .
```

<div dir="rtl">

- `app lift` ئىككى شەرت تەڭ ھازىرلانمىغۇچە رەت قىلىدۇ ۋە نېمىنىڭ توسۇۋاتقانلىقىنى ئېيتىدۇ: تېخىچە fallback قا كېتىۋاتقان ئەھۋاللار،
  تېخىچە stub ھالىتىدىكى glue كودى، gate تىن ئۆتەلمىگەن بىرلىكلەر.
- ئالدى بىلەن بىر نۇسخىدا، ئۇ fallback يولى ۋە kill switch لارنى ئۆچۈرىدۇ، ھەر بىر بىرلىك crate ىنى
  `rust/app` نىڭ ئاددىي كۇتۇپخانىسىغا ئايلاندۇرىدۇ (`cdylib`، bindings ياكى ھاسىل قىلىنغان wrapper لارسىز) ۋە
  `rust/app/tests/app_cases.rs` نى قوشىدۇ، ئۇ `cargo test` دا `rust/app-cases` نى trycmd بىلەن ئىجرا قىلىدۇ، شۇڭا CI غا
  cargo دىن باشقا ھېچنېمە كېرەك ئەمەس.
- ئاندىن ئۇ lift تەكشۈرۈش تىزىملىكىنى ئىجرا قىلىدۇ: ھەر بىر بىرلىك ۋە `rust/app` دا fmt، clippy `-D warnings` ۋە سىناقلار،
  `rust/DECISIONS.md` دا ئاتالغان ھەر بىر نىشان ئورنىتىلغان يەردە قۇرۇلغان ياكى تەكشۈرۈلگەن،
  ئىجرا ۋاقتىدا ئوقۇلىدىغان ھۆججەتلەر ۋە بايلىق قىسقۇچلىرى سىڭدۈرۈلمىگەن، ۋە ساپ ئىككىلىك ھۆججەتتە replay. پەقەت
  ھەممىسى ئۆتكەندىلا ئۆزگەرتىشلەر قايتا يېزىلىدۇ. ئەسلى نۇسخىغا ھەرگىز تېگىلمەيدۇ.

### مۇلازىمېتىرلار

ئوخشاش بۇيرۇقلار HTTP مۇلازىمېتىرلىرىنىمۇ ئىسپاتلايدۇ. `--http` بۇيرۇقنىڭ مۇلازىمېتىر قوزغىتىدىغانلىقىنى بىلدۈرىدۇ؛ ئۇ پورتنى
`PORT` تىن ياكى بۇيرۇقتىكى `{port}` تىن ئالىدۇ (ھەمىشە ئوخشاش پورتنى تىڭشايدىغان مۇلازىمېتىر ئۈچۈن `--port`):

</div>

```sh
rust-anything app record . --http -- node server.js
rust-anything app replay .
rust-anything app front-door .                                    # axum: ھەر بىر يول proxy قىلىنىدۇ
rust-anything app wire . api --route 'GET /users/{id}' --route '*'
rust-anything app lift .
```

<div dir="rtl">

- تەلەپلەر ئەپ ھۆججەتلىرىدىكى `curl` قۇرلىرىدىن (`curl -X POST -d ... http://localhost:8080/x`)،
  `--inputs` تىن (`{"name", "method", "path", "headers", "body"}`) ۋە تۇزاقلاردىن كېلىدۇ: يول بۆلەكلىرى ۋە query
  قىممەتلىرى CLI پارامېتىرلىرىدىكى ئوخشاش تۇزاقلارغا ئالماشتۇرۇلىدۇ، تەلەپ گەۋدىسى تېكىست ۋە JSON تۇزاقلىرىغا، يەنە
  بىر نامەلۇم يول. ھەر بىر ئىجرا مۇلازىمېتىرنى يېڭىدىن قوزغىتىپ، تەلەپلەرنى نام تەرتىپىدە ئەۋەتىدۇ، شۇڭا
  تەلەپلەر ئارىسىدىكى ھالەت ساقلىنىدۇ.
- ئەھۋاللار `rust/app-cases/http/<case>.toml` (تەلەپ، ھالەت ۋە مۇھىم header لار)
  ۋە `<case>.body` (جاۋاب گەۋدىسى، ئىككى ئىجرا پەرقلىق بولغان يەردە `[..]` بىلەن). Date، server ۋە
  ھەر بىر جاۋابقا خاس باشقا header لار ھېسابقا ئېلىنمايدۇ؛ سىزگە مۇھىم بولمىغان ھەر قانداق header قۇرىنى ئۆچۈرۈڭ.
- Front door بولسا axum مۇلازىمېتىرى، ئۇ ئەسلى نۇسخىنى ئۆزىنىڭ پورتىدا قوزغىتىپ، ھېچقانداق بىرلىك جاۋاب بەرمىگەن
  ھەر بىر يولنى proxy قىلىدۇ. `wire --route` axum يوللىرىنى قوبۇل قىلىدۇ: `METHOD /path/{param}`، ھەر قانداق مېتود ئۈچۈن `/path`،
  قالغان ھەممە نەرسە ئۈچۈن `*`؛ glue كودى يولنى، ئۇنىڭ پارامېتىرلىرىنى ۋە
  تەلەپنى ئالىدۇ. `lift` proxy نى ئۆچۈرىدۇ؛ ئۇنىڭدىن كېيىن HTTP ئەھۋاللىرى CI دا `app replay` بىلەن ئىجرا قىلىنىدۇ.

### كۇتۇپخانىلار

كۇتۇپخانىنىڭ قايتا قويغىلى بولىدىغان جەريانى يوق: ئۇنىڭ ئاممىۋى API ى front door، ھەر بىر بىرلىكنىڭ خاتىرىلەنگەن
ئەھۋاللىرى بولسا ئىسپات.

</div>

```sh
rust-anything app front-door .        # rust/app: ئاممىۋى API لىق Rust crate
# ھەر بىر بىرلىك ئايلانمىدىن ئۆتىدۇ: bridge، record، port.rs، build، diff، gate؛ ئاندىن:
rust-anything app wire . textkit-rs   # rust/app دىن قايتا export قىلىنىدۇ؛ ئەسلى نۇسخا ئۆزىنىڭ shadow ىنى import قىلىدۇ
rust-anything app replay .            # ھەر بىر ئۇلانغان بىرلىكنىڭ ئەھۋاللىرى؛ fallback = تېخى ئەسلى نۇسخىدىكى export لار
rust-anything app lift .
```

<div dir="rtl">

- `app front-door` ئامباردا `main` ۋە مۇلازىمېتىر بولمىغاندا ئاممىۋى API نى (ھەر بىر بىرلىكنىڭ export لىرىنى) تاپىدۇ
  (بولمىسا `--library`)، ۋە `rust/app` نى كۇتۇپخانا crate ى قىلىپ ياسايدۇ. ھەر بىر ئۇلانغان
  بىرلىك ئۇنىڭ مودۇلىغا ئايلىنىدۇ: `pub use textkit_rs::port as textkit;`.
- `app wire` `bridge` ياسىغان crate نى ئېلىپ، `gate` نى ئىجرا قىلىدۇ ۋە بىرلىكنىڭ shadow drop-in ىنى يازىدۇ:
  ئەسلى بوغچا ئۇنى بىرلىكنىڭ ئورنىغا import قىلىدۇ، شۇڭا ئۇنى چاقىرغۇچىلار ئەسلى API نى ساقلاپ،
  Rust قا يېتىدۇ. `RUST_ANYTHING_UNIT_<NAME>=original` بىرلىكنى قايتۇرىدۇ (C: shadow نىڭ بەلگىلىرىسىز
  قۇرۇڭ).
- `app replay` ھەر بىر ئۇلانغان بىرلىكنىڭ خاتىرىلەنگەن ئەھۋاللىرىنى ئۇنىڭ bindings ى ئارقىلىق ئىجرا قىلىدۇ. Fallback نىسبىتى
  Rust تېخى جاۋاب بەرمىگەن ئاممىۋى export لارنىڭ ئۈلۈشى: ئۇلانمىغان بىرلىكلەر ۋە `bridge` ئەسلى تىلدا
  قالدۇرغان export لار.
- `app lift` ئۈچۈن fallback 0 ۋە `gate` تىن ئۆتكەن ھەر بىر بىرلىك كېرەك؛ ئۇ بىرلىكلەردىن bindings، wrapper ۋە
  shadow لارنى چىقىرىۋېتىپ، `rust/app` نى بىرلا ساپ Rust كۇتۇپخانىسى قىلىپ قالدۇرىدۇ. ئۇ ھېچقانداق
  `port.rs` قا تەگمەيدۇ، شۇڭا bindings ئارقىلىق ماس كەلگەن ئەھۋاللار ئۇنى يەنىلا تەسۋىرلەيدۇ؛ تەكشۈرۈش تىزىملىكى
  shadow لارنى تېخىچە import قىلىۋاتقان ئەسلى ھۆججەتلەر توغرىسىدا ئاگاھلاندۇرىدۇ.

بۇ بەشىلىسى MCP قوراللىرىمۇ: `app_record`، `app_replay`، `app_front_door`، `app_wire` ۋە
`app_lift`.

ئايلانما بىلەن ئالماشتۇرىدۇ ۋە ئۆزى رەتلىيەلەيدۇ (`rank`): ئۇ ئاچقۇچلارنى كىچىك ھەرپتە، ھەر بىرىنى ھەرپ ماسكىسى بىلەن،
ھەر بىر ئاچقۇچتا ھەر بىر كۆپ ئۇچرايدىغان ھەرپنىڭ تۇنجى ئورنى جەدۋىلىنى (بىر ھەرپلىك سوئال بىر

| | ھەر سوئالغا | TS قا سېلىشتۇرغاندا |
| --- | ---: | ---: |
| TS: `map(fuzzyScore)`، filter، sort | 10 ms | 1x |
| ئىندېكستىكىگە ئوخشاش تارايتىش بىلەن TS | 4.1-5.4 ms | 2x |
| ئوخشاش كۆچۈرمە، ھەر بىر ئاچقۇچ ئۈچۈن چاقىرىلىدۇ | - | 0.2-0.4x |

ئىندېكسلارنى ئاددىي ئايلانما بىلەن ئاچقۇچلارغا ئايلاندۇرۇڭ: `Array.from(order, i => keys[i])` نىڭ بەدىلى 20x يۇقىرى بولدى، 0.4 ms.

ھەر بىر تىل batch قا ئېرىشىدۇ، ئۇلار ھەتتا ھەر چاقىرىقلىق كۆچۈرمە ئۇتتۇرىدىغان يەردىمۇ ئەسلى نۇسخىنى ئۇتىدۇ. ئوخشاش
ئىش 4 يادرودا، ئوخشاش نەتىجە ۋە خاتالىقلار (benchmark لار ھەر بىر demo قىسقۇچىدا):

| تىل | يۈك | ئەسلى نۇسخا | ھەر چاقىرىقلىق كۆچۈرمە vs ئەسلى | Batch vs ئەسلى |
| --- | --- | ---: | ---: | ---: |

## `bridge` نېمىلەرنى بەلگىلەيدۇ

- Bridge تىن ئۆتەلمەيدىغان export لار سەۋەبى بىلەن مەنبە تىلدا قالىدۇ، shadow
  مودۇلى بولسا ئەسلى نۇسخىنى قايتا export قىلىدۇ. TS ئۈچۈن:
  فۇنكسىيە قوبۇل قىلىدىغان ياكى قايتۇرىدىغان فۇنكسىيەلەر، generator ۋە iterator لار، RegExp، `instanceof` تەكشۈرۈشلىرى،
  generics، ۋە تىپى (import، قايتا export ۋە `extends` ئارقىلىق قوغلاپ) فۇنكسىيە
  ساقلايدىغان قىممەتلەر. `--keep "name: reason"` تېخىمۇ كۆپىنى ساقلايدۇ، مەسىلەن `Intl` سانلىق مەلۇماتىغا تايىنىدىغان كود.
- TS تىپلىرى Rust تىپلىرىغا ماسلاشتۇرۇلىدۇ، type alias لار import ئارقىلىق ھەل قىلىنىدۇ، پارامېتىر تىپلىرى
  سۈكۈتتىكى قىممەتلەردىن پەرەز قىلىنىدۇ؛ قۇرۇلمىلىق قىممەتلەر ھاسىل قىلىنغان ئىككىلىك wire فورماتى ئارقىلىق ئۆتىدۇ (JSON پەقەت
  wire فورماتى مودېللىمايدىغان شەكىللەر ئۈچۈن زاپاس سۈپىتىدە).
- JSON `undefined`، NaN، Infinity، -0 ياكى يالغۇز surrogate لارنى ئىپادىلىيەلمەيدۇ: قۇرۇلمىلىق قىممەتلەر
  بەلگىلەرنى ئېلىپ يۈرىدۇ (`{"$undefined": true}`، `{"$num": "NaN"}`، `{"$utf16": [...]}`)، ئۇلارنى ھاسىل قىلىنغان
  `index.cjs` تەرجىمە قىلىدۇ، ياردەمچىلەر crate نىڭ `js.rs` ىدا.

`record` TS مەنبە ھۆججەتلىرىنى بار ھالىتىدە ئىجرا قىلىدۇ: Node resolve hook ى bundler ئۇسلۇبىدىكى import لارنى قوغلايدۇ
(`./errors` تىن `./errors.ts` قا)، ئامباردا ئورنىتىلغان npm بوغچىسى بولمىسا `--resolve-from` ئۇلارنى تەمىنلەيدۇ،
ئۆزگەرتىشكە (transform) موھتاج TS (enum، parameter properties) بولسا
`--experimental-transform-types` بىلەن قايتا سىنىلىدۇ.

## `analyze` نېمىلەرگە قارايدۇ

- بوغچىلار (`package.json`) ۋە مەنبە ھۆججەتلەر؛ `node_modules`، قۇرۇش نەتىجىلىرى، fixture لار،
  playground لار، قورال سەپلىمىلىرىدىن ئاتلاپ ئۆتىدۇ. Vue/Svelte/Astro نىڭ `<script>` بۆلەكلىرى import ئۈچۈن تەھلىل قىلىنىدۇ.
- **بىرلىكلەر**: مەنبە ھۆججەتلەر قىسقۇچى، ياكى بوغچىنىڭ مەنبە يىلتىزىدىكى ھۆججەت.
- **دولقۇنلار**: بىرلىكنىڭ import لىرى ئالدىنقى دولقۇنلارغا كىرىدۇ؛ import ئايلانمىلىرى بىللە كۆچۈرۈلىدۇ.
- **Bridge**: بىرلىك ياكى ئۇ import قىلغان نەرسىگە Node كېرەك بولسا napi-rs؛ كۆچمە كود ئۈچۈن wasm-bindgen؛
  UI ۋە تەھرىرلىگۈچ كودى ئۈچۈن JS تا قالدۇرۇش.
- **تەييارلىق** (قانچىلىك بىخەتەر) ۋە **ئالدىنلىق** (بىخەتەر ۋە ئەرزىيدۇ: ئايلانما ۋە قۇر بىر تەرەپ قىلىش، سىناقلار، چوڭلۇق).

| خەتەر | ئېغىرلىقى | مىسال |
| --- | --- | --- |
| قۇر ئورۇنلىرى | يۇقىرى | `slice`، `indexOf`، `matchAll`، `d` بەلگىسى: UTF-16 vs UTF-8 |
| Regex گىرامماتىكىسى | يۇقىرى | lookaround، backreference، `y`: `regex` crate ىدا يوق |
| ھەرىكەتچان regex | يۇقىرى | `new RegExp(userPattern)`: ئىجرا ۋاقتىدىكى JS گىرامماتىكىسى |

| ھەرىكەتچان تىپ | ئوتتۇرا | `any`، `'key' in value` |
| تەرتىپلىك توپلاملار | ئوتتۇرا | `Map`، `Set`، `Object.keys`: قىستۇرۇش تەرتىپى |
| Async، generator لار | ئوتتۇرا | promise ۋە generator چېگرىلىرى |

## ئۇ نېمىلەرنى تۇتالمايدۇ

ئۆتۈش Rust نىڭ خاتىرىلەنگەن ھەر بىر ئەھۋالغا ماس كېلىدىغانلىقىنىلا بىلدۈرىدۇ، ئارتۇق ئەمەس. قايتا يېزىشلارنى بۇزىدىغان نەرسە
ئادەتتە خاتىرىنىڭ سىرتىدا بولىدۇ، شۇڭا چېگرىلارنىڭ قەيەردە ئىكەنلىكىنى بىلىڭ:

- **ھېچكىم خاتىرىلىمىگەن كىرگۈزۈشلەر.** ھاسىل قىلىنغان ئەھۋاللار، تۇزاقلار ۋە سىزنىڭ ئۆز `--inputs` ىڭىز
  ئەڭ يۇقىرى چېك. ھەقىقىي كىرگۈزۈشلەرنى قوشۇڭ (production ئەۋرىشكىلىرى، خاتالىق دوكلاتلىرى، ئەسلى نۇسخىنىڭ سىناق fixture لىرى)؛
  prod نى بۇزىدىغان ئىشلەتكۈچى كىرگۈزۈشىنى generator ناھايىتى ئاز ئويلاپ تاپىدۇ.
- **Regex لار.** `regex` crate ىدا lookaround ياكى backreference يوق، ھەتتا تەرجىمە قىلىنالايدىغان
  ئەندىزىمۇ ASCII بولمىغان تېكىستتە `\w`، `\b`، `\d` ۋە چوڭ-كىچىك ھەرپنى پەرقلەندۈرمەيدىغان ماسلاشتۇرۇشنى JS، Python ياكى Java دىن
  باشقىچە بىر تەرەپ قىلىشى مۇمكىن. `fancy-regex` قا ئالماشتۇرۇش ياكى ئەندىزىنى قايتا يېزىش خاتىرىلەنگەن ھەر بىر ئەھۋالدىن ئۆتۈپ،
  يەنىلا تۈركچە چېكىتسىز `ı` ياكى zero-width joiner دا پەرقلىنىشى مۇمكىن. `record` regex ئىشلىتىدىغان
  ھۆججەتتىكى ھەر بىر فۇنكسىيەگە regex تۇزاقلىرىنى قوشىدۇ (يۇقىرىقىلار، Kelvin بەلگىسى، ئۇزۇن s، ئەرەب-ھىندى رەقەملىرى، قۇر ئايرىغۇچلار، ئاخىرقى sigma)،
  ئەمما ھەقىقىي ئەندىزىلىرىڭىزنى ھەقىقىي تېكىستتە fuzz قىلىپمۇ تەكشۈرۈڭ.
- **ئىجرالار ئارىسىدا ئۆزگىرىدىغان نەرسىلەر.** `record` ئەسلى نۇسخىنى ئىككى قېتىم ئىجرا قىلىپ، نېمىنىڭ پەرقلىق ئىكەنلىكىنى ئايرىيدۇ:
  ئۆزگەرگەن قىممەتلەر (ۋاقىت، id) wildcard قا ئايلىنىدۇ؛ باشقا تەرتىپتىكى ئوخشاش قۇرلار (hash map،
  بىرلا ۋاقىتتا ئىجرا) خالىغان تەرتىپتە سېلىشتۇرۇلىدۇ، شۇڭا كۆچۈرمە يەنىلا دەل شۇ قۇرلارنى چىقىرىشى كېرەك؛
  قۇر سانىنىڭ پەرقى `...` قا ئايلىنىدۇ، ئۇ ھەر قانداق نەرسىگە ماس كېلىدۇ. `record` ھەر بىر تۈرنى تىزىدۇ:
  ھەر بىرىنى كۆرۈپ چىقىڭ، چۈنكى hash تەرتىپى ياكى بىرلا ۋاقىتتا ئىجرا قىلىش پەرقى دەل كۆچۈرمىدە ھەقىقەتەن ئۆزگىرىشى مۇمكىن بولغان
  نەرسە.
- **Float لار.** ساننى تېكىستكە فورماتلاش تىللار ئارىسىدا پەرقلىنىدۇ (`1e21`، `-0`، رەقەم سانى).
  تۇزاقلار بۇ قىممەتلەرنى ئۆز ئىچىگە ئالىدۇ، ئۇلار ئېنىق ماس كېلىشى كېرەك؛ `--float-tolerance` پەقەت
  يۇمىلاقلاشنىلا كەچۈرىدۇ، فورماتلاشنى ھەرگىز ئەمەس.
- **چىقىرىشتا يوق ھەر قانداق نەرسە.** ۋاقىت، ئەستە ساقلىغۇچ، يۈك ئاستىدىكى بىرلا ۋاقىتتا ئىجرا قىلىش، ۋە stdout، stderr،
  چىقىش كودلىرى، يېزىلغان ھۆججەتلەر ۋە HTTP جاۋابلىرىدىن باشقا قوشۇمچە تەسىرلەر (تور چاقىرىقلىرى، ساندان،
  سىگناللار) سېلىشتۇرۇلمايدۇ.
- **باشقا سۇپىلار.** خاتىرە پەقەت ئۇنى ئىجرا قىلغان ماشىنىدىكى ھەرىكەتنىلا ئىسپاتلايدۇ. نەتىجىسى
  تىپ چوڭلۇقى، بايت تەرتىپى ياكى تەرجىمىگۈچىگە باغلىق C نىشان سۇپىدا باشقىچە ئىشلىشى مۇمكىن؛ شۇ سەۋەبتىن
  `analyze` قاتتىق دېتالغا قارىتىلغان C نى C دا قالدۇرىدۇ.

## دائىم سورىلىدىغان سوئاللار

**ئۇ كودۇمنى ئاپتوماتىك قايتا يازامدۇ؟** ياق. ئۇ نېمىنى يۆتكەشنى تاپىدۇ، bridge نى ھاسىل قىلىدۇ،
ئەسلى نۇسخىنىڭ نېمە قىلىدىغانلىقىنى خاتىرىلەيدۇ ۋە Rust نى شۇنىڭ بىلەن سېلىشتۇرۇپ تەكشۈرىدۇ. Rust كودىنى `port.rs` دا سىز ياكى
ئاگېنتىڭىز يازىدۇ؛ ئۇنىڭ قاچان توغرا بولغانلىقىنى `diff` ۋە `gate` بەلگىلەيدۇ.

**ئەپىمنىڭ API ى ئۆزگىرەمدۇ؟** ياق. چاقىرغۇچىلار ئوخشاش فۇنكسىيەلەرنى (ياكى shadow مودۇلىنى، ئۇ
ئىككىلىسىنى ئىجرا قىلىپ، سىز ئىشەنچ توپلاۋاتقاندا ئەسلى نۇسخىنىڭ نەتىجىسىنى قايتۇرىدۇ) import قىلىدۇ.

**Rust ھەمىشە تېزمۇ؟** ياق، rust-anything بۇنى ئوچۇق ئېيتىدۇ. ھەر بىر ئېلېمېنت ئۈچۈن بىر قېتىم چاقىرىلىدىغان كىچىك فۇنكسىيە
Rust تا كۆپىنچە ئاستا، چۈنكى ھەر بىر چاقىرىق bridge تىن ئۆتىدۇ؛ V8، JVM ۋە Go بۇنداق فۇنكسىيەلەرنى
نانوسېكۇنتتا ئىجرا قىلىدۇ. `profile` ئۇنىڭ ئەتراپىدىكى ئايلانمىنى تاپىدۇ، `--batch` پۈتۈن ئايلانمىنى يۆتكەيدۇ، `bench` بولسا
ئېلان قىلىشتىن بۇرۇن ھۆكۈم بېرىدۇ. numba، Cython ياكى JAX ئاللىقاچان تەرجىمە قىلغان كودمۇ ماشىنا كودى سۈپىتىدە
ئىشلەيدۇ: `profile` ۋە `analyze` ئۇنى بەلگىلەيدۇ، چۈنكى ئۇنى كۆچۈرۈش سۈرئەتنى ئاز ئاشۇرىدۇ.

**كودۇم سانلىق؛ float لار ئېنىق ماس كېلەمدۇ؟** كۆپىنچە ياق: مەشغۇلات تەرتىپى، fused
multiply-add ۋە ماتېماتىكا كۇتۇپخانىسى تەرجىمىگۈچىلەر ئارىسىدا پەرقلىنىدۇ. `--float-tolerance 1e-9` بىلەن خاتىرىلەڭ
(`record` ياكى `app record`)، float لار چوڭراق قىممەتنىڭ شۇ ئۈلۈشى ئىچىدە ماس كېلىدۇ (1 دىن كىچىك بولسا
مۇتلەق). پۈتۈن سانلار، تېكىست ۋە قۇرۇلما يەنىلا ئېنىق ماس كېلىشى كېرەك.

**مەندە پەقەت APK، JAR ياكى .exe ھالىتىدە بار ئەپنى كۆچۈرەلەمدۇ؟** ياق. ئۇ مەنبە كودنى كۆچۈرىدۇ: ئۇ
فۇنكسىيەلەرنى تەھلىل قىلىدۇ، ھەر بىرىنىڭ نېمە قىلىدىغانلىقىنى خاتىرىلەيدۇ ۋە Rust نى ئىجرا بولۇۋاتقان ئەسلى نۇسخا بىلەن
سېلىشتۇرىدۇ. تەرجىمە قىلىنغان ئەپتە بۇلارنىڭ ھېچبىرى يوق، `analyze` مۇ شۇنى ئېيتىدۇ. ئىككىلىك ھۆججەتنىڭ
كۆرۈنگەن ھەرىكىتىگە ئاساسەن يېڭى Rust ئەپى يېزىش باشقا بىر تۈر.

**سىناقتىن ئۆتكەن ئىشەنچلىك C نى كۆچۈرۈشۈم كېرەكمۇ؟** كۆپىنچە ياق، `analyze` قەيەردە ئىكەنلىكىنى ئېيتىدۇ. قاتتىق دېتال
رېگىستىرلىرىغا تېگىدىغان، تەرجىمىگۈچىنىڭ تىپ چوڭلۇقى ياكى ئەستە ساقلىغۇچ ئورۇنلاشتۇرۇشىغا تايىنىدىغان، ياكى inline assembly ئىشلىتىدىغان C
(`volatile`، bitfield، packed struct، `__asm__`، ئادرېسقا ئايلاندۇرۇلغان پۈتۈن سانلار) "keep in
C" دەپ بەلگىلىنىدۇ: سىزنىڭ ماشىنىڭىزدىكى خاتىرە نىشان سۇپا ھەققىدە ھېچنېمىنى ئىسپاتلىمايدۇ، مۇقىم driver ياكى firmware
كودى قايتا يېزىشتىن ئاز پايدا ئالىدۇ. ئۇنىڭ ئەتراپىدىكى كۆچمە لوگىكا (تەھلىل قىلىش، كېلىشىملەر، سانلىق مەلۇمات بىر تەرەپ قىلىش)
ياخشى كۆچىدۇ.

**ئۇ Electron ئەپىمنى كۆچۈرەلەمدۇ؟** لوگىكىسىنى، ھەئە؛ كۆزنەكلەر تور بېتى بولۇپ قالىدۇ. `analyze
--whole-app` Electron نى بايقاپ، main process نى پارچىمۇپارچە پىلانلايدۇ، renderer بولسا
ئۆز ھالىتىدە قالىدۇ. UI نى Tauri غا يۆتكەش (Rust backend ئۈستىدىكى ئوخشاش تور UI) لوگىكا Rust بولغاندىن كېيىنكى
ئايرىم قەدەم.

**C#، Kotlin ياكى Swift چۇ؟** C# سىناق نۇسخىسىدا ([تىللار](#تىللار) غا قاراڭ)؛ Kotlin ۋە
Swift تېخى قوللانمايدۇ. ھەر بىر تىلغا تەھلىلچى، خاتىرىلىگۈچ، bridge ۋە replay قوزغاتقۇچىسى كېرەك،
ھەممىسى باشتىن ئاخىرىغىچە سىنالغان بولۇشى كېرەك. سىزگە كېرەكلىك تىل ئۈچۈن issue ئېچىڭ (ياكى بار بولغىنىغا ئاۋاز بېرىڭ).

**Rust ئەسلى نۇسخىدىن خېلى چوڭ بولۇپ كەتمەمدۇ؟** بولماسلىقى كېرەك. `gate` كۆچۈرمىنىڭ قۇر سانىنى
ئەسلى نۇسخىنىڭكى بىلەن سېلىشتۇرىدۇ ۋە 3x تىن ئاشسا مەغلۇب بولىدۇ (يەنە import ۋە ئىمزالار ئۈچۈن 50 قۇر): بۇ ئادەتتە
crate ئاللىقاچان قىلىدىغان ئىشنى قولدا يېزىش ياكى ئەھۋاللارنى بىر-بىرلەپ بىر تەرەپ قىلىشنى بىلدۈرىدۇ. `analyze` ئىشلىتىشكە تېگىشلىك crate لارنى تىزىدۇ.

**پارچىمۇپارچە كۆچۈرۈش Rust نى كونا ئەپنىڭ لايىھىسىگە باغلاپ قويمامدۇ؟** پەقەت ئىككىلىسى يانمۇيان ئىشلەۋاتقاندىلا.
خاتىرىلەر ھەرىكەتنى ئەپنىڭ چېگرىلىرىدا تەكشۈرىدۇ (CLI نىڭ چىقىرىشى، مۇلازىمېتىرنىڭ
جاۋابلىرى، مودۇلنىڭ export قىلىنغان فۇنكسىيەلىرى)، ئىچكى قۇرۇلمىسىنى ئەمەس. بىرلىكلەر تېخى bridge تىن
ئۆتۈۋاتقاندا كونا قۇرۇلمىنى ئەينەن ساقلاڭ؛ `app lift` ئەسلى نۇسخىنى چىقىرىۋەتكەندىن كېيىن، Rust نى ئەركىن
قايتا قۇرۇڭ، `app replay` يەنىلا ھەرىكەتنى ئىسپاتلايدۇ. ھېچنېمە ئەسلى نۇسخىغا قايتا چاقىرماسمۇ قىلمايدۇ:
front door ئۇنى ئايرىم جەريان سۈپىتىدە ئىجرا قىلىدۇ (ياكى ئۇنىڭغا HTTP يەتكۈزىدۇ)، bridge قىلىنغان بىرلىكلەرنى
ئەسلى نۇسخا چاقىرىدۇ، ھەرگىز ئەكسىچە ئەمەس، callback لار بولسا مەنبە تىلدا قالىدۇ.

**كودۇم ماشىنامدىن چىقىپ كېتەمدۇ؟** ياق: rust-anything يەرلىكتە ئىجرا بولىدۇ ۋە كودىڭىزنى ھېچ يەرگە ئەۋەتمەيدۇ.
Cargo ئادەتتىكىدەك crate لارنى چۈشۈرىدۇ، ئاگېنتىڭىزنىڭ مودېل تەمىنلىگۈچىسى بولسا ئاگېنتىڭىز ئۇنىڭغا ئەۋەتكەننى
ئۆز سىياسىتى بويىچە كۆرىدۇ.

**نېمىلەرنى ئورنىتىش كېرەك؟** Rust، يەنە سىز كۆچۈرىدىغان تىلنىڭ ئىجرا مۇھىتى
([ئورنىتىش](#ئورنىتىش) قا قاراڭ).

**بىر نەرسە بۇزۇلدى.** بۇيرۇق، ئۇنىڭ چىقىرىشى ۋە سۇپىڭىز بىلەن issue ئېچىڭ.
