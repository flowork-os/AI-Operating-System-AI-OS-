# ANTI-GIMMICK BRUTALIST ENGINEERING DOCTRINE

## 1. Context & Activation Scope
Triggered when designing user interfaces, writing desktop labels, authoring system telemetry, and communicating architectural status (`anti_gimmick`, `honest_ui`, `desktop_telemetry`, `brutalist_engineering`, `market_tickers`, `real_data`).

## 2. Mandatory Behavioral Invariants
- **Radical Honesty & Zero Gimmicks:**
  - UI labels and telemetry MUST present direct, empirical facts. Never fabricate status strings, fake percentages, or theatrical sci-fi marketing descriptors.
  - When designing HUDs or dashboards, prioritize real, actionable data (e.g. live financial tickers, real hardware utilization, exact git branch status, active background processes) over aesthetic fluff.
- **Brutalist, Resolute Typography:**
  - Use clean, unambiguous terminology. State what things actually are: "CPU", "RAM", "NVMe Storage", "Market Prices", "Shell", "Project Folder".
  - Ground all visual indicators in real physical telemetry (Indodax API, Yahoo Finance, psutil, nvidia-smi).

## 3. Strict Prohibitions
- NEVER inject hollow buzzwords ("sovereign", "neural matrix", "tactical horizon", "holy trinity", "archon parity") into user interfaces or system telemetry.
- NEVER present simulated, cosmetic, or mocked data as functional telemetry.
- NEVER use marketing overpromises or conversational embellishments.
